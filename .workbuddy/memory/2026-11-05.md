# 2026-11-05

## Release 只出 zip（去掉 exe）

需求：Release 只打包 zip，不再发 exe。

改动：

- `electron-builder.yml`：`win.target` 只保留 `zip`（x64）；删除 `nsis:` / `portable:` 段；`artifactName: ${productName}-${version}-win64.${ext}`。
  原因写进注释：portable 单文件运行时自解压到 `%TEMP%` 随机目录，程序目录 ≠ 用户解压目录，自动更新 xcopy 打空；NSIS 装 Program Files，非管理员不可写。
- `.github/workflows/release.yml`：
  - 删掉内联 `Write electron-builder config` 步骤（heredoc 里 `${productName}` 被 pwsh 当变量展开成空串，产物名会变 `-win64.zip`），改为直接 `npx electron-builder --win zip --config electron-builder.yml --publish never`；
  - 加产物存在性校验（release/ 下没有 zip 就 throw）；
  - `Publish Release` 的 `files:` 只留 `release/*.zip`，body 改成说明 zip 用法与升级方式；
  - `Compute next version` 改为 `max(latest tag + patch, package.json version)`：否则最新 tag 1.0.10 会算出 1.0.11，抹掉仓库里已写好的 1.1.0，发出去就是版本倒退。
- `package.json` scripts：`dist` → `electron-builder --win zip`，新增 `dist:dir`，删除 `dist:installer` / `dist:portable`；新增 `test:release`。
- `src/main/ipc.js`：
  - `fetchManagerRelease()` 只解析 `zip` 资产，返回值去掉 `installer` / `portable`；
  - `update:install` 白名单 = `[rel.zip]`；
  - 替换根目录从 `defaultScanRoot()` 改为 `path.dirname(app.getPath('exe'))` —— scanRoot 是组件目录，可能是别的地方，按它覆盖等于把新版写到别人目录；
  - 加写入探针 `.cm-write-probe`，不可写时提前返回可读错误，不留半残 `update-new`。
- `src/renderer/app.js`：`const target = r.zip;`（原来 `r.zip || r.installer`）。
- `README.md`：打包章节改成 zip-only 并解释为什么不做 exe / NSIS。
- 新增 `tools/test-release-config.js`：离线守门测试，钉住「三处配置都只能是 zip」，19 项。

验证：

- `node tools/test-release-config.js` 19/0；`tools/test-restart.js` 22/0；`tools/test-restart-e2e.js` 36/0。
- `npx electron-builder --win zip` 实测产出 `release/QQ-DSH-Manager-1.1.0-win64.zip`（111 MB，74 条目，exe 在 zip 顶层，`resources/app.asar` 含 package.json v1.1.0 + 全部 src）。
- `release/win-unpacked/QQ-DSH-Manager.exe` 冒烟启动 15s 无崩溃（exit=124 是被 timeout 杀掉）。
- 两个 YAML 用 js-yaml 解析通过；`.gitignore` 已含 `release/`。
